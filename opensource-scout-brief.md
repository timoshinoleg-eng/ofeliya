## 1. Контекст и рамки (что мы ищем и зачем)

OFELIYA — юрлицо, фаза 0 без монетизации. Продукт: **roguelike-выживание
(Vampire-Survivors-like)** внутри мини-приложения мессенджера MAX. Забег ~5 минут,
босс на 5:00 = победа, управление одним пальцем.

Железобетонные ограничения, которые **обязаны** учитываться при отборе:

- **Стек фронта:** Phaser **3.90** + TypeScript (**strict**) + **Vite** (есть этап сборки,
  `vite build`, прод — статика по HTTPS). ESM, tree-shaking. Текущий gzip-бандл ~352 КБ.
- **Бюджет на новые зависимости:** суммарно **≤150 КБ gzip**, без per-frame аллокаций.
- **Цель по производительности:** 60 FPS на Android среднего класса (System WebView,
  WebGL). Часть вебвью не тянет WebGL2 → эффекты должны иметь fallback.
- **Платформа:** MAX — мобильный вебвью. Доступен только **MAX Bridge** (`window.WebApp`):
  `initDataUnsafe` (id/имя/аватар), `shareContent({text, link})`, `HapticFeedback`,
  `BackButton`, `SecureStorage`. Диплинк запуска: `https://max.ru/<bot>?startapp=<payload>`.
  Из API **недоступны** платежи / реклама / нативные лидерборды / реальный мультиплеер
  «из коробки». → Никаких фич, требующих обязательного внешнего SDK или сервера синхронизации
  (кроме явно планируемого нашего Node-процесса).
- **Аудио:** WebAudio-синтез, разблокировка по первому жесту (политики автоплея вебвью).
- **Арт:** генерируется кодом (неон-минимализм, тёмный фон, форма+обводка). Внешние
  ассеты переносимы на 100% при совместимой лицензии.
- **Бэкенд:** пока нет. Планируется Node-процесс рядом с ботом MAX (`@maxhub/max-bot-api`),
  хостинг — **РФ**. **152-ФЗ:** персданные (ники, счёта, рекорды) храним/обрабатываем только
  на серверах в РФ; зарубежные SaaS «как есть» отпадают, самохостинг обязателен.
- **Точки расширения нашего кода** (сюда встраиваются находки): `src/game/config.ts`
  (весь баланс), `UpgradeSystem.ts` (новые улучшения), `WaveDirector.ts` (спавн/боссы),
  `RunState.ts` (статы), `MaxBridge.ts` (платформа), `Sfx.ts` (звук), `SaveSystem.ts`
  (сохранения), сцены `Menu`/`Game`/`UI`.

## 2. Критерии отбора (жёсткий фильтр)

| Критерий | Требование | Обоснование |
|---|---|---|
| **Лицензия** | `MIT`, `BSD-2/3`, `Apache-2.0`, `ISC`, `Unlicense`, `CC0`; ассеты — `CC0` или `CC-BY` (с атрибуцией) | Закрытое коммерческое использование без раскрытия исходников |
| **Лицензия — СТОП** | `GPL`, `LGPL` (для статич. бандла фронта), **`AGPL`** любой, `CC BY-SA` | AGPL = раскрытие всего продукта при сетевом использовании; LGPL/GPL — copyleft-риски при линковке |
| **Язык/форм-фактор** | JS / TS; **npm-пакет с ESM + типами** (у нас TS strict) либо самодостаточный модуль; совместим с Vite | Есть этап сборки — можно ставить зависимости, но они должны tree-shake-аться и иметь d.ts |
| **Зависимости** | 0 или минимум транзитивных; без нативных модулей; без React/Vue | Бюджет ≤150 КБ gzip и строгость типов |
| **Активность** | последний коммит/релиз ≤ 24 мес; не archived; issues не «кладбище» | Проект живой, не мертвый форк |
| **Вес** | клиент-либа вписывается в бюджет ≤150 КБ gzip суммарно; микро-либы предпочтительнее | Мобильный мессенджер |
| **Интегрируемость** | framework-agnostic, без обязательного внешнего CDN/редиректов, совместим с MAX Bridge и вебвью | Архитектура продукта |
| **Качество** | тесты / демо / документация API; понятный код; для Phaser-плагинов — заявленная версия 3.60+ и наличие типов | Быстрая верификация и портируемость |

### Исправленная лицензионная справка (частая ошибка)
- **Umami — MIT** (принимаем, self-host на РФ-хостинге). *Ранее ошибочно числился как AGPL —
  это неверно.*
- **PostHog core — MIT** (принимаем как альтернативу; тяжёлый Docker ≈4 ГБ RAM).
- **Plausible CE — AGPL** (отклоняем). **Matomo — GPL** (отклоняем).
- Вывод: self-host аналитику воронки берём из MIT-инстансов (Umami/PostHog), НЕ пишем свою
  «с нуля» ради лицензии.

## 3. «Золото» против «меди» — как не брать поверхностное

**Медь (игнорировать):**
- Гиганты-фреймворки ради хайпа: Phaser/Babylon/Three/Pixi (Phaser у нас уже есть),
  движки уровня «GDevelop/Construct export».
- Мега-популярные репозитории «на слуху» и верхушка `awesome-*` списков без конкретики.
- Любой проект, требующий React-окружения или нативной сборки под платформу.
- Готовые «Vampire Survivors clones» на Unity/Godot/React — не переносимы в наш TS-движок.

**Золото (искать):**
- **Узкоспециализированные** одноцелевые библиотеки и отдельные алгоритмы (seeded-RNG,
  ghost-replay, tween/easing, частицы, Web-Audio-синтез, генерация share-картинок на canvas).
- **Phaser-плагины** с MIT и типами, точечно закрывающие джус/UI (rexrainbow и аналоги).
- **CC0-ассет-паки** (иконки апгрейдов, спрайты взрывов) — перенос 100%, стиль-фильтр:
  неон на тёмном, читаемость при 360 px.
- Референсные **реализации механик на чистом TS/JS** (поведение врагов/боссов/оружий),
  где арты вырезаем, а код поведения берём.
- **Self-host инстансы MIT** (Umami/PostHog) и лёгкие серверные шаблоны (Node+SQLite
  лидерборд, Colyseus-комнаты).
- Процедурные генераторы, микро-движки, утилиты доступности; экспорты game-jam (JS13K,
  Ludum Dare, GitHub Game Off).

**Сигналы золота:** высокое «полезность / вес», ≤1–2 зависимости, понятный код,
«Used by» у качественных проектов, автор отвечает, пермиссивная лицензия, ESM+типы,
работает в мобильном вебвью без внешних CDN.

## 6. Протокол верификации (обязателен для каждого кандидата)

Порядок проверок; кандидат выбывает на первом провале:
1. **LICENSE существует и совместим** (MIT/BSD/Apache-2.0/CC0/CC-BY-ассеты). GPL/LGPL/AGPL/
   CC BY-SA — выбывает. Ссылка на файл LICENSE обязательна (и проверка, что внутри файлов
   нет иной лицензии при MIT в package.json).
2. **Зависимости:** читаем package.json — ноль или минимум транзитивных; **ESM**; для
   Phaser-плагинов — заявленная версия 3.60+, наличие типов/d.ts (у нас TS strict).
3. **Активность:** последний коммит/публикация ≤ 24 мес, не archived, issues не «кладбище».
4. **Демо:** playable-демо/видео/скриншоты. Нет демо — минус балл и пометка.
5. **Чтение интеграционной поверхности:** указать конкретные файлы/классы, которые возьмём,
   примерный LOC, есть ли хардкод платформы/ассетов/глобального состояния.
6. **Совместимость со средой:** работает ли в мобильном вебвью без внешних CDN и редиректов;
   для эффектов — **WebGL1 fallback** (часть вебвью не тянет WebGL2); для серверного —
   1 Node-процесс, деплой в РФ, без обязательной внешней БД.
7. **Вес:** оценка добавляемого gzip (клиент) — вписывается ли в бюджет §1 (≤150 КБ суммарно).

Для **топ-3 финалистов** (и только для них): клонировать, `npm install && npm run build`,
прогнать демо, приложить вывод (собралось/ошибки, версия Phaser/Node). Это **аналитическая**
проверка, не внедрение в наш продукт.

## 7. Скоринг (для сортировки таблицы)

Оценка 0–10 = **Влияние на игру** (0–4: насколько заметно улучшает UX/виральность) ×
**Перенос %** (0–3: 100%→3, ≥70%→2, ≥50%→1, <50%→0) ×
**Дешевизна внедрения** (0–3: часы→3, дни→2, неделя+→1),
минус **2 за блокер** (лицензия/вес/платформа/нетипы).

**Порог включения в таблицу — ≥4.** Дополнительно как жёсткие гейты: License fit = 5
(обязательно) и Integrability (ESM+типы, вебвью) ≥ 4.

| Параметр | Вес | Что оцениваем |
|---|---|---|
| License fit | x3 | пермиссивная и без copyleft-ловушек (файлы, не только package.json) |
| Integrability | x3 | ESM + TS-типы, без внешних CDN, работает в вебвью |
| Activity | x2 | коммиты ≤24 мес, отвечают на issues |
| Quality | x2 | тесты / демо / документация |
| Weight | x1 | вписывается в бюджет ≤150 КБ gzip |
| Relevance | x2 | закрывает конкретный разрыв из п. 4 / RESEARCH_REPORT |

## 8. Красные флаги (автовычет)

- Лицензия `AGPL`/`GPL`/`LGPL`/`CC BY-SA` (для статич. фронт-бандла).
- Хардкод Telegram/VK/иной WebApp API без слоя абстракции (должен быть адаптируем под MAX Bridge).

- Проекты «AI-generated, as is» без тестов и демо.
- Постэффекты без **WebGL1 fallback** (часть вебвью не тянет WebGL2).
- Последний коммит > 24 мес; `archived:true`; «abandoned fork».
- В `package.json` MIT, но внутри файлов — иная лицензия.
- Нет ESM / нет типов при TS strict / не собирается под Vite.

## 10. Правила честности

- Каждый факт о кандидате: либо доказательство (файл/строка/ссылка), либо пометка «предположение».
- Не смешивать «нашёл» и «знаю из памяти»: память — только как наводку, затем обязательная проверка.
- Не выдумывать проекты, URL и проценты. Не нашёл кандидата по категории — написать
  «нет, пишем сами».
- **Стартовые гипотезы из RESEARCH_REPORT.md считать наводками, а не ответами** — перепроверить
  и дополнить собственным поиском (особенно совместимость конкретных rex-плагинов с Phaser 3.90,
  даты релизов Colyseus, точный вес Tone.js, лицензию jsfxr-пакета).
