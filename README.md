# OFELIYA

Рогалик-выживание в стиле Vampire Survivors — мини-приложение для мессенджера **MAX**.
Персонаж стреляет автоматически, игрок управляет только движением, собирает фрагменты данных,
выбирает улучшения и удерживает ЯДРО OFELIYA до критической фазы: на 5:00 появляется босс,
победа засчитывается только после его уничтожения.

## Стек

- **Phaser 3 + TypeScript + Vite** — сама игра. Основной визуал генерируется кодом; внешние
  ассеты — аудио в `public/audio/`, грузятся по сети и не входят в JS-бандл:
  **SFX — Kenney CC0** (`public/audio/sfx/`), **музыка — коллекция CC0 Music на OpenGameArt**
  (`public/audio/music/`). Обе лицензии CC0 1.0, атрибуция не требуется.
- **MAX Bridge** (`window.WebApp`, подключается CDN-скриптом в `index.html`) — launch/user context,
  viewport/capability helpers, хаптика и шаринг результата. `initDataUnsafe` используется только
  как удобный клиентский контекст и **не считается доверенной авторизацией**. Для серверной
  идентификации необходимо передавать подписанную строку `window.WebApp.initData` на доверенный
  backend и валидировать её там. В обычном браузере bridge безопасно деградирует в no-op
  (см. `src/systems/MaxBridge.ts`).
- **Шрифт** — дисплейный **Chakra Petch** (OFL, самохостится в `public/fonts/*.woff2`, подгружается
  до старта Phaser в `main.ts`). При ошибке загрузки используется системный fallback.
- **`@maxhub/max-bot-api`** — возможная зависимость будущей серверной части бота; клиентская
  сборка OFELIYA от неё не зависит.

## Запуск

```bash
npm install
npm run dev      # дев-сервер http://localhost:5173
npm run build    # прод-сборка в dist/ (tsc + vite)
npm run preview  # локальный просмотр прод-сборки
```

Управление: тап/драг по экрану — виртуальный джойстик (появляется под пальцем),
на десктопе — WASD/стрелки.

## Публикация в MAX

1. `npm run build` → в `dist/` лежит статика с относительными путями (`base: './'`).
2. Разместить `dist/` на HTTPS-хостинге.
3. В кабинете MAX указать HTTPS URL мини-приложения у бота.
4. Перед добавлением серверных рейтингов/персональных данных реализовать серверную проверку
   подписанного `window.WebApp.initData`; `initDataUnsafe` для этого не использовать.

## Структура

```text
src/
  main.ts               — запуск Phaser (+ window.__game в dev для smoke/QA)
  scenes/               — Boot, Menu, Game, UI
  game/                 — Player/Enemy/Bullet/Gem, RunState, WaveDirector, UpgradeSystem,
                          EvolutionSystem, AchievementSystem, RunMilestones, identity, config
  systems/              — MaxBridge, SaveSystem, Sfx, AtmosphereSystem, VfxSystem
```

Вся интеграция с MAX изолирована за `MaxBridge`; gameplay остаётся работоспособным в обычном
браузере. Баланс (урон, волны, кривая опыта, босс) находится в `src/game/config.ts`.

## Цикл забега

0:00–5:00 — волны (ШУМ → ИМПУЛЬС → РАЗРЫВ), элиты/АНОМАЛИИ и presentation milestones.
На 5:00 появляется босс. Уничтожение босса — победа; смерть — проигрыш.

Внутри забега доступны три эволюции сборки:

- **ПРИЗМА**;
- **ОРЕОЛ**;
- **СИНГУЛЯРНОСТЬ**.

Локально сохраняются достижения, количество забегов, lifetime kills, история эволюций и
раздельные временные рекорды:

- **лучшее выживание** — максимальное время проигранного забега;
- **лучшая победа** — минимальное время успешного убийства босса.

Также сохраняются максимальные убийства и уровень ядра.

## Quality gate

Pull requests проходят GitHub Actions:

```bash
npm ci
npm run build
```

Перед публичным MAX-релизом дополнительно выполняется браузерный smoke на мобильных viewport'ах,
проверка повторных restart/lifecycle и позднего боя с VFX.
