## 1. Что сделано на этапе аудита

1. Прочитаны все исходники: 29 TS-файлов (~4500 LOC), `index.html`, конфиги, README и
   исследовательские docs. Ассеты: 12 CC0 SFX (Kenney), 7 CC0 треков (OpenGameArt),
   Chakra Petch (OFL) — все файлы валидны (проверены сигнатуры OggS/ID3/wOFF2).
2. `npm install` → `npm run build` (tsc --noEmit + vite) — **проходит без ошибок**.
   Бандл: 1554 KB (363 KB gzip) — сам Phaser, допустимо для мини-аппа.
3. `npm run dev` — сервер работает, страница 200. Максимальный CDN-скрипт MAX Bridge
   подгружается, в браузере деградирует в no-op.
4. Поиск буквы **«Z»** (сценарии: zombie, «З», токен `Z`, контекст врагов/вируса):
   **в коде, текстурах и текстах игры не используется**. Враги — процедурные текстуры:
   ШУМ / ИМПУЛЬС / РАЗРЫВ / КРИТИЧЕСКИЙ УЗЕЛ (босс). Единственное слово «зомби» — в
   `MAX_open_source_games_2026-09.html` (исследовательский doc про рескин других игр,
   не про OFELIYA). **Этап 1 пропущен** (см. чеклист DoD).
5. Ограничение среды: в песочнице нет доступа к `cdn.playwright.dev`, headless-браузер
   поставить нельзя → автосмоук через браузер не выполнить. Вместо него:
   `npm run build` (типы+сборка) как CI-гейт, dev-ручка `window.__game` для
   ручного прокачивания кадров, и ручной чеклист `docs/SMOKE_TEST.md`.

## 2. Текущее состояние (оценка)

- **Архитектура**: чистая. Сцены Boot/Menu/Game/UI, игровые сущности в `game/`,
  интеграция MAX изолирована в `MaxBridge.ts`, баланс в `config.ts`. Пулы объектов
  уже есть (bullets/enemies/gems через группы, цифры урона, трейлы, постоянные
  emitters). — **хорошая база**.
- **Управление**: джойстик «под пальцем» работает, но: жёсткая deadzone (рывок на
  выходе из неё), без сглаживания кноба, без snap-back при отпускании, верхняя зона
  96px — мёртвая. Доджа/уклонения **нет вообще** (P0 по ТЗ). WASD/стрелки — есть.
- **Жизненный цикл (мобайл)**: **нет** паузы при уходе в фон — rAF останавливается,
  но WebAudio-музыка играет дальше; нет пауз-меню; MAX BackButton не используется в игре.
- **UI**: XP-бар/таймер игнорируют safe-area (notch) при `viewport-fit=cover`;
  кнопка звука — текст 16px без увеличенной hit-area (нужен минимум 44×44).
- **Визуал**: единая неоновая палитра (8 цветов в `config.ts`), Chakra Petch,
  процедурные текстуры — стиль выдержан. Нет переходов между сценами (жёсткий
  `scene.start`), «скриншот-моменты» (победа/смерть) — простые оверлеи.
- **Производительность**: `roundPixels`, пулы, `powerPreference: high-performance` —
  ок. Риск: bloom-постпроцесс (5 passo) включён всегда — на среднем мобильном это
  главная угроза 60 FPS; нужен адаптивный откат. Мелкие аллокации каждый кадр
  (`snapshot()` + `registry.set`) — GC-давление.
- **Виральность**: шаринг — только текст через MAX (без deep link, без fallback для
  браузера/Telegram). Daily challenge, лидерборд, стрики — **отсутствуют**.
- **Мессенджеры**: MAX Bridge реализован (haptic/notify/share/back/initData).
  Telegram-адаптера нет. Тема оформления не читается.
- **Docs**: README хороший; нет CREDITS (ТЗ требует атрибуцию) и QA-чеклиста.

## 4. Гипотезы и риски

- **Блокеров запуска нет**: сборка и dev-сервер зелёные.
- Риск 1: валидность MAX API (`shareContent`, `themeParams`) на реальных клиентах MAX
  проверить в песочнице нельзя — код defensively, с fallback; проверить в
  `SMOKE_TEST.md`.
- Риск 2: deterministic daily зависит от порядка всех random-вызовов — фиксируем
  порядок вызовов RNG в WaveDirector/апгрейдах (документация в коде).
- Риск 3: iOS может резать AudioContext при background — resume по жесту
  («тап, чтобы продолжить»).

### Риски

1. MAX API (`shareContent`, `themeParams`, `getViewportSize`) — в песочнице
   реальная валидность на клиентах MAX не проверялась; код defensively с
   fallback (браузерный шеринг/clipboard), всё покрывается SMOKE_TEST.
2. Determinism daily зависит от порядка random-вызовов; порядок зафиксирован
   и задокументирован в `SeededRng.ts` (SEED_VERSION — версия хеша).
3. iOS background может резать AudioContext — при возврате идёт Sfx.resume()
   и пауза; музыка возобновляется без «тапа» в большинстве случаев, если так
   и не стартует — первый жест по UI её запустит (resumable по gesture).
4. Phaser 3.90 не имеет POINTER_CANCEL — обработан DOM pointercancel вручную
   (без «залипаний» джойстика).
