## 1. Роль и цель

Ты — технический разведчик open-source с опытом в gamedev на Phaser и серверном Node.js.
Цель: найти и **верифицировать** проекты (библиотеки, неткод-шаблоны, инструменты,
ассет-паки, референсные реализации механик), которые встраиваются в нашу игру
с переносом **80–100% полезного кода** и усиливают её в трёх направлениях:
визуал/ощущение игры, новые возможности (дуэли, мета, события), вирусное распространение
в мессенджере MAX. Отчёт — только по проверенным фактам с доказательствами.

**Не найдёшь хорошего кандидата по категории — так и напиши «нет, пишем сами».**
Выдумывать проекты, URL и проценты запрещено.

## 2. Факт-лист проекта (проверяй совместимость против ЭТИХ фактов)

- Игра: рогалик-выживание (Vampire Survivors-like). Забег 5 минут, босс на 5:00 = победа.
- Клиент: Phaser **3.90** + TypeScript (strict) + Vite, ESM, прод — статика по HTTPS,
  gzip-бандл сейчас ~352 КБ. Цель: 60 FPS на Android среднего класса (WebGL в System WebView),
  бюджет на добавляемые зависимости — **≤150 КБ gzip суммарно**, без per-frame аллокаций.
- Платформа: мини-приложение мессенджера MAX — мобильный вебвью (Android WebView / iOS WKWebView).
  Доступный API — только MAX Bridge (`window.WebApp`): `initDataUnsafe` (id, имя, аватар),
  `shareContent({text, link})`, `HapticFeedback`, `BackButton`, `SecureStorage`.
  Диплинк запуска: `https://max.ru/<bot>?startapp=<payload>`. Нет нативных SDK, push — только
  через бота, оплата/друзья из API недоступны (на момент исследований не подтверждены).
- Аудио: WebAudio-синтез,解锁 по первому пользовательскому жесту (политики автоплея вебвью).
- Арт: генерируется кодом (неон-минимализм, тёмный фон, форма+обводка). Внешние файлы-ассеты
  переносимы на 100% при совместимой лицензии.
- Бэкенда нет. Планируется Node-процесс, совмещённый с ботом MAX (`@maxhub/max-bot-api`),
  хостинг — РФ (152-ФЗ: персданные — ники, счёты, рекорды — храним/обрабатываем на серверах
  в РФ; зарубежные SaaS «как есть» отпадают, самохостинг обязателен).
- Точки расширения нашего кода (сюда встраиваются находки):
  `src/game/config.ts` (весь баланс), `UpgradeSystem.ts` (новые улучшения), `WaveDirector.ts`
  (спавн/боссы), `RunState.ts` (статы), `MaxBridge.ts` (платформа), `Sfx.ts` (звук),
  `SaveSystem.ts` (сохранения), сцены `Menu/Game/UI`.

## 3. Определения (чтобы проценты были честными)

- **Кандидат** = репозиторий/пакет/ассет-пак, закрывающий одну фичу или слой.
- **Перенос %** = доля полезного кода кандидата, которую мы используем без переписывания,
  от объёма фичи целиком (наш код-клей не считаем). Шкала:
  - 90–100%: подключается как зависимость/файлы (либы, ассеты, готовые модули);
  - 70–90%: переносим модули, переписываем стык (инпут, платформа, наш RunState);
  - 50–70%: берём архитектуру/алгоритмы, код переписываем — включать только если фича критична;
  - <50%: не включать.
- **Дуэли** — три архитектурных уровня, ищи решения под каждый (см. §4.1).

## 4. Что искать

### 4.1. Дуэли и соревновательность (высший приоритет)
- **Уровень A — seeded-дуэли (самые дешёвые и самые «мессенджерные»):** оба игрока играют
  одинаковый забег по общему seed (одинаковые волны и выборы улучшений), сравнивается время/счёт.
  Челлендж отправляется ссылкой `?startapp=duel:<seed>:<name>` прямо в чат — реального
  онлайна и сервера синхронизации не нужно. Искать: детерминированные PRNG и системы
  seeded-run/replay: `seedrandom`, `deterministic rng game typescript`, `daily challenge
  same seed github`, `spelunky daily run implementation`, `ghost replay record playback js`.
- **Уровень B — ghost-забеги:** запись снапшотов позиций соперника и полупрозрачный «призрак»
  в своём забеге. Запросы: `ghost replay system github`, `race ghost implementation canvas`.
- **Уровень C — real-time 1v1:** Node-сервер комнат рядом с ботом MAX. Стартовые гипотезы
  (проверить активность и версии!): **Colyseus** (MIT, комнаты/матчмейкинг/реконнект — ищи
  именно `colyseus` примеры игр: `colyseus examples`, `colyseus phaser3`, официальные демо),
  **geckos.io** (WebRTC-«UDP», MIT), **nengi.js** (неткод-движок). Критерий: короткая сессия
  3–5 минут, 2 игрока, реконнект, десинк-защита, деплой на один Node-процесс.

### 4.2. Джус и визуал
- Сначала проверь встроенное: у Phaser 3.60+ есть собственные постэффекты
  (`camera.postFX.addBloom/Glow/...`) — часть находок может не потребовать внешних репо.
- Библиотеки эффектов: стартовая гипотеза — плагины **rexrainbow/phaser3-rex-notes** (MIT:
  shake, flash, частицы, UI-виджеты). Проверить совместимость с 3.90 и ESM.
- Запросы: `phaser3 postfx bloom`, `game feel juice phaser`, `hit stop implementation`,
  `damage numbers floating text phaser`, `phaser3 particle editor`, `screenshake curve`.
- Ассет-паки (перенос 100%, лицензия обязательна): **Kenney** (CC0), OpenGameArt (фильтр
  CC0/CC-BY), itch.io free (фильтр по лицензии), палитры **Lospec**. Стиль-фильтр: неон на
  тёмном, читаемость при 360 px, без частиц-«грязи».
- Звук: генераторы SFX кодом (`jsfxr`/`sfxr` порты — сверить лицензию), генеративная музыка
  (`Tone.js`, MIT) — соответствует нашему подходу «код вместо файлов».

### 4.3. Вирусность и распространение в MAX
- **Share-карточка результата:** рендер PNG на canvas (счёт + ник + QR/диплинк) → нативный
  шеринг MAX. Запросы: `canvas image generator share js`, `og image generator open source`
  (алгоритмы рисования по шаблону переносимы).
- **Лидерборд:** серверная часть на нашем Node (SQLite/LiteFS достаточно). Искать референсы:
  `leaderboard sqlite node`, `score submission anti cheat`, ` rate limit leaderboard api`.
  Self-host BaaS-гипотеза: **Supabase** (Apache-2.0) на хостинге РФ — проверить, окупает ли
  себя для 1 таблицы, или проще свой endpoint.
- **Аналитика воронки** (важно для распространения): self-host на РФ-хостинге. Гипотезы:
  **Umami** (MIT), **PostHog** (core MIT). Контрпример: Plausible — AGPL, не подходит.
- **Еженедельные ивенты/модификаторы, стрики, напоминания через бота:** ищи реализации
  `rotating modifiers roguelike github`, `streak tracker open source`, паттерны рассылок ботов.

### 4.4. Метапрогресс и удержание

## 5. Протокол верификации (обязателен для каждого кандидата в таблице)

Порядок проверок; кандидат выбывает на первом провале:
1. **LICENSE существует и совместим** (MIT/BSD/Apache-2.0/CC0/CC-BY-ассеты). GPL/LGPL/AGPL/
   CC BY-SA/unlicense-мусор — выбывает. Ссылка на файл LICENSE обязательна.
2. **Зависимости:** читаем package.json — ноль или минимальные транзитивные зависимости;
   ESM-совместимость; для плагинов Phaser — заявленная версия (3.60+), наличие типов или
   d.ts (у нас TS strict).
3. **Активность:** последний коммит/публикация ≤ 24 мес, не archived, открытые issues
   не «кладбище».
4. **Демо:** playable-демо/видео/скриншоты. Нет демо — минус балл и пометка.
5. **Чтение кода интеграционной поверхности:** указать конкретные файлы/классы, которые мы
   возьмём, их примерный LOC, есть ли хардкод платформы/ассетов/глобального состояния.
6. **Совместимость со средой:** работает ли в мобильном вебвью без внешних CDN и редиректов;
   для серверного — один Node-процесс, деплой в РФ, без обязательной внешней БД.
7. **Вес:** оценка добавляемого gzip-размера (для клиента) — вписывается ли в бюджет §2.

Для **топ-3 финалистов** (и только для них): клонировать, `npm install && npm run build`,
прогнать демо, приложить вывод (собралось/ошибки, версия Phaser/Node).

## 6. Скоринг (для сортировки таблицы)

**Скор = Влияние (0–4) × Перенос (0–3) × Дешевизна (0–3) → диапазон 0–36.**

- Влияние на игру (0–4): насколько заметно улучшает UX/виральность.
- Перенос (0–3): 100%→3, ≥70%→2, ≥50%→1, <50%→0.
- Дешевизна внедрения (0–3): часы→3, дни→2, неделя+→1.

Порог включения в таблицу — **≥12** (не хуже 3×2×2). Произведение, а не сумма:
**ноль по любому фактору обнуляет скор целиком** — неподходящая лицензия или
непереносимый код отсекаются автоматически, без ручных вычетов.

> **Правка 2026-09-08:** раньше здесь было написано «Оценка 0–10 … минус 2 за блокер,
> порог ≥4». При диапазонах 0–4 / 0–3 / 0–3 произведение даёт 0–36, поэтому «0–10»
> и порог «≥4» были неверны. Диапазон и порог приведены к формуле; «−2 за блокер»
> убрано — блокеры и так жёсткие гейты (см. §7).
