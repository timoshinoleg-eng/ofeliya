Ключевое ограничение, которое меняет всю стратегию

Проверено лично по официальной документации dev.max.ru (06.09.2026): в MAX Bridge нет ни платежей, ни рекламы, ни лидербордов, ни мультиплеера, ни облачных сохранений. Доступны только shareContent/shareMaxContent, DeviceStorage и SecureStorage (лимит 10 ключей), биометрия, NFC, QR, хаптик. ✅

Также: каталога мини-приложений в MAX не существует — приложение привязано к чат-боту и открывается кнопкой «Играть». Органической дистрибуции нет. ✅

Следствие: лидерборды, дуэли, платежи, аналитику и рекламу придётся строить на своём бэкенде и на внешних SDK — с отдельным риском модерации. Это заложено во все оценки ниже.

0Что усилено в брифе перед запуском поиска

Добавленный шагЗачем
Дистрибуция как отдельный стоп-критерийБриф исходно исходил из наличия каталога в MAX. Его нет. Любая игра без собственного трафика получает 0 установок независимо от качества — это проверяется до оценки механики.
Верификация через GitHub API, а не через поискЗвёзды, лицензия SPDX и дата коммита берутся из /search/repositories?repo=…, а не из выдачи. Исключены «призрачные» репозитории. Проверено 11 репозиториев повторно, лично.
Происхождение ассетов = отдельный аудитБриф требовал проверить assets/. Усилено: ищем указание источника в README. Отсутствие упоминания = риск «стоп», даже при MIT на код.
Проверка чужого брендаДобавлен критерий, которого не было: Pac-Man, Tetris, Mario и т.п. —商标. Проекты с чужим IP отсекаются даже при чистой лицензии кода.
Проверка на «некоммерческое» заявление в READMEКод может быть GPL/MIT, но автор отдельно запретить коммерцию. Найден реальный кейс — см. раздел 6.

Выводы для запуска HTML5-игры

  1. Технически порог входа низкий: обычный HTML5, любой https-хостинг, статический URL обновляется мгновенно.
  2. Органического трафика нет. Дистрибуция = свой бот + внешний трафик (каналы MAX, рассылки, лендинг, закупка). Единственная игровая витрина — @vk_games_bot.
  3. Монетизация не закрыта платформой: свою рекламную сеть и свою платёжку нести самому, с риском упереться в правила о внешних интеграциях и «согласовании акций».
  4. Код VK Mini Apps не переносится как есть. Нужен адаптерный слой: другой глобальный объект, нет VKWebApp-событий, оплат и лидербордов. VKUI официально не поддерживается.
  5. Юридический вход закрыт для нерезидентов РФ.
  6. Аудитория огромная, но взрослая. Под 12–18 придётся закупаться отдельно, а не рассчитывать на ядро MAX.
  7. Модерация без SLA и без прописанной грани по азартным механикам → согласование формулировок до разработки.

Что вымерло, что выжило

Вымерло: чистый tap-to-earn и кликер без геймплея. Сооснователь Notcoin, 05.05.2025: «tap-to-earn games are probably dead because they're not sustainable». ✅

Выжило: (1) хаб мини-игр внутри мини-аппа (Catizen); (2) PvP/дуэли с турнирами; (3) социальные сессии 2–5 мин (кости, RPS); (4) ежедневные задания; (5) коллекционирование + обмен.

Не переносится в MAX: airdrop/токен как единственный смысл; рефералка как ядро петли; награда за приглашение как основной стимул.

ARPDAU по мини-аппам не найден ни в одном публичном источнике ❓. Косвенные данные: CPC ~$0,01 при CTR 20–40% в Tier-2/3 (PropellerAds, 12.2025) ✅; ARPPU экосистемы $4,20 (2024) → $9,50+ (оценка 2026) ⚠️.

10.2 Рекомендация

Топ-1: Мердж-физика — маршрут C (свой код на matter.js + Kenney CC0)

Почему: единственный кандидат с максимальным баллом по виральности (15/15), а виральность — это единственный канал роста при отсутствии каталога. Физика генерирует мемный контент сама: скриншот поля — это рекламный креатив, сделанный игроком бесплатно. Тяга доказана цифрами (8 млн копий), лицензии чистые на 100% (MIT + CC0), ниша в MAX пустая.

Запасной: 2048 + дуэли (87/100) как софт-лонч за 1 неделю. Он не станет хитом, но за 0,5–1,5 человеко-недели даст ответ на главный вопрос проекта: какова реальная конверсия бота MAX в игрока и сколько стоит установка. Этот ответ определяет бюджет для топ-1.

Порядок действий: сначала 2048 (1,5 недели, измерить трафик) → затем, если CAC укладывается в модель, мердж-игра (3,5 недели) → затем хаб из 3 игр с кросс-промо.

Почему survivor-like всё равно проигрывает, даже если механика горячая

  1. Нет годной веб-реализации. Единственный популярный клон matthiasbroske/VampireSurvivorsClone (274★, MIT) — это Unity/C#, для веба неприменим. Зрелых HTML5-реализаций с доказанной тягой не существует.
  2. Phaser 3 + React = тяжёлый бандл. Замерено 06.09.2026: Phaser 3.90 — 1,14 МБ минифицированный, 309 КБ gzip (✅). Плюс React 18, плюс ассеты (спрайты врагов, частицы). Лимит бандла в MAX не опубликован ❓.
  3. Слабый шаринг-результат. «Я выжил 4:32» проигрывает картинке с горой фруктов. Для MAX, где шаринг — единственный канал роста, это критично.
  4. Объём доработки недооценён. Survivor-like требует 20+ сбалансированных апгрейдов, тайминги волн, спрайты 10+ типов врагов. Реально 8–12 человеко-недель, а не «наибольший интерес по соотношению трудозатрат».
  5. Прямой клон коммерческой игры. Vampire Survivors — чужой IP. Механику копировать можно, название и арт — нет.

Что взять, если направление survivor/выживание принципиально

Единственный живой и массовый проект в этой зоне — pshenok/server-survival (6 397★, MIT, коммит 26.08.2026, vanilla JS + Three.js, сборка не нужна). Это tower defense/survival с волнами, а не Vampire Survivors, но это единственное, что реально можно взять и довести.

Переосмысление под мессенджер: не «выживи 15 минут», а «отбей волну за 2–3 минуты» — волна становится естественной единицей шаринга («я дошёл до волны 20»). Отдельный стоп-фактор: папка assets/ без указания происхождения — аудит обязателен до первой строки кода.
