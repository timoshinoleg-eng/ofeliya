# QA: фиксированные состояния экрана мутаций (A/B/C) + визуальный перенос «Био-мембрана»

База сверки данных: `main 2bd6320b1d7f8e1076e7dd70dfafb46800efd86a`. Ветка
`qa/mutation-screen-states` (коммиты QA-набора + визуальный перенос экрана A).
Браузерная проверка (Chromium, ноутбук) — пройдена; физическая приёмка на
Samsung S20+ — **NOT_RUN, за владельцем**.

## Что перенесено

Экран выбора мутации (`UIScene.showLevelUp`) собран заново по утверждённому
направлению «Био-мембрана»:

- тёмные панели поверх боя; заголовок «ВЫБЕРИ МУТАЦИЮ» и одна подсказка
  «Нажми на карточку, чтобы выбрать» (не-трофейный путь);
- раскладка измеряемая: высота каждой карточки считается по фактическому
  тексту, стек центрируется под заголовком; при нехватке места (короткие
  экраны) сначала режется декор — отступы, промежутки, служебный футер
  спецкарточек, кегли не опускаются ниже минимумов (11 px);
- отдельная форма «ПОСЛЕДНИЙ НОСИТЕЛЬ»: Условие и Эффект полным текстом, цена
  отдельной плашкой «При срабатывании: −25% прогресса текущего уровня»,
  облик — одной вторичной строкой (без раскрываемой панели);
- обычные карты: строки характеристик «название слева — значение справа»,
  единица привязана к числу неразрывным пробелом; значения считаются из
  текущего состояния забега (`getUpgradeBeforeAfter`), а не захардкожены;
- реакция нажатия: карточка сама отвечает (подсветка мембраны + масштаб 0,97),
  отпускание пальца за пределами карточки выбора не даёт;
- выбор идёт штатным путём `acceptChoiceClick → chooseUpgrade`, пауза,
  церемонии и очередь предложений сохранены.

## Как открыть каждое состояние

QA-гейт: dev-сервер (`npm run dev`) или сборка с `VITE_QA_TOOLS=1`. Без гейта
параметр игнорируется. Открыть игру и сразу стартовать забег — модалка
выбора появится сама через обычный путь, выбор — обычным тапом.

| Состояние | URL | Что внутри |
|---|---|---|
| A | `?qaMutation=A` | «ПОСЛЕДНИЙ НОСИТЕЛЬ» (легендарная) + «РЕЦЕПТОРНЫЙ ЗАХВАТ» + «ЦИТОЛИЗ», свежее состояние |
| B | `?qaMutation=B` | «РНК-АФФИНИТЕТ» + «РЕЦЕПТОРНЫЙ ЗАХВАТ» + «ЦИТОЛИЗ», стеки nova 3/3 + magnet 1/2 |
| C | `?qaMutation=C` | «СИНГУЛЯРНОСТЬ» (критическая) + «РЕЦЕПТОРНЫЙ ЗАХВАТ» + «ЦИТОЛИЗ», стеки nova 3/3 + magnet 2/2 |

### На телефоне (Samsung S20+)

1. Сборка с QA-флагом: `VITE_QA_TOOLS=1 npm run build` → отдать `dist/` с
   любого статического хоста в локальной сети (или открыть dev-сервер
   ноутбука по LAN-адресу: `npm run dev -- --host`, телефон в той же сети).
2. Открыть `http://<host>/?qaMutation=A` (затем B, C).
3. Проверить по чек-листу ниже. Скриншоты — системным жестом; запись экрана —
   штатной функцией Samsung.

## Чек-лист приёмки

- Ровно три карточки; порядок как в таблице выше.
- Пары «было → стало» с названием характеристики и единицей:
  A — время заражения **1250 → 1025 мс**, радиус заражения **58 → 62,6 ед.**;
  урон взрыва **26 → 33,8** (без единицы), радиус взрыва **150 → 162 ед.**.
  B — радиус подбора РНК **121,5 → 164 ед.**; выбор «РНК-аффинитета» лишь
  выполняет условия рецепта (СИНГУЛЯРНОСТЬ появится следующим предложением),
  эволюция сама не применяется.
- «ПОСЛЕДНИЙ НОСИТЕЛЬ»: Условие, Эффект, цена и строка про облик читаются до
  тапа. Выбор резервирует страховку; срабатывание — только от смертельного
  урона: остаётся 1 прочности, теряется 25 % прогресса уровня, обычные враги
  исчезают, форма мутации 8 секунд.
- «СИНГУЛЯРНОСТЬ» отличается от легендарной формой/композицией, полный эффект
  и рецепт видны без обрезания; после выбора меняется облик и открывается
  условие «Цепи лизиса».
- Один тап выбирает; быстрый повторный тап ничего не выбирает; отпускание
  пальца за пределами карточки ничего не выбирает; после последнего выбора
  пауза снимается и бой продолжается.
- 320×568 и 390×844: три предложения, важные условия и цена помещаются без
  обрезания. Короткий 320×520 проходит squeeze-проходом (футер-декор
  спецкарточек убирается, контент сохраняется).

## Команды проверок (ноутбук)

```
npm run test:mutation-states        # контракт данных A/B/C на исходниках игры
npm run test:mutation-copy         # копир экрана: заголовок, форма носителя, единицы
npm run test:mutation-before-after # пары «было → стало» из живого состояния
npm run test:ui-copy               # пины копира каталога
npm run test:choice-integrity      # тап/повторный тап/очередь (нужен Vite :5173)
npm run test:legendary-layout      # 88 сценариев легендарок, 320×520 внутри
node scripts/mutation-states-probe.cjs  # браузер: состояния, тапы, реакция нажатия,
                                        # release-outside, церемонии, страховка, .webm
```

Проба поднимает свой Vite на :5199 (переопределить `OFELIYA_PORT`), пишет
кадры и записи в `docs/qa/mutation-states-2026-11-09/`.

## Артефакты

- `320x568-A-choice.png`, `390x844-A-choice.png` — экран A на двух размерах.
- `390x844-A-tap-and-return-record.webm` — один выбор с возвратом в бой.
- `390x844-A-insurance-*` — пик страховки, срабатывание от смертельного урона,
  возврат формы через 8 с (`-trigger-record.webm`).
- `320x568/390x844-B-*`, `*-C-*` — рецепт magnet→СИНГУЛЯРНОСТЬ и эволюция C.
- `report.json` — сводка пробы.

## Границы

Только экран мутаций. Шансы выпадения, перенос билда в «Сердце», Кодекс и
Коллекция — отдельные задачи. B и C использованы для проверки длинного текста
и рецепта; их финальная визуальная доводка — после приёмки A. Скриншоты и
записи здесь — браузерные; телефонные — за владельцем.
